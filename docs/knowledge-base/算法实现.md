## 本仓库 Stage 2 工程约定（核心闭环已落地；评测后置）

用户锁定决策见 [`docs/online-rl/stage2_survey.md`](../online-rl/stage2_survey.md) 第 1 节。代码在 `src/smolvla_rltoken/rl/`、`rollout/`、`envs/chunk_env.py`。入口 `python scripts/train_online_rl.py`（YAML `configs/rl/actor_critic.yaml`）。

- 整局 PegInsertion（标准 `reset`，对齐 SFT eval），warmup 后全程 Actor；无人手 handover、无精细门控。
- Actor 直接 \(\pi(x,\tilde a)\)，**不是**残差。2 层 MLP，hidden 256，**LayerNorm+ReLU**。部署取 \(\mu\)，训练 \(\sigma=0.05\)。
- V1 **不做** stride=2（一条执行 chunk = 一条 transition）。`stride: 1` 写在 YAML；`--check` 拒绝其它值。
- 稀疏奖励：逐步 \(r_t=\mathbf{1}[\texttt{info["success"]}]\)；忽略 dense `env.reward`。`terminated`（success）清零 bootstrap，`truncated`（200-step）不清零。TD 用 \(\gamma^n\)（`n_steps`），不是固定 \(\gamma^C\)。
- 无人类干预；`ref_dropout=0.5`（只 mask Actor 输入的 \(\tilde a\)，BC 目标用未 mask 的；TD target 的 \(\tilde a'\) 也 dropout，与 afengleafs 一致）；\(\beta=1.0\)。注意 BC 项是 `mean((a-ã)^2)`（over \(C\times 8\) 个元素），等于论文 \(\|\cdot\|_2^2\) 的 **1/80**；要更强约束就调大 `bc_beta`，不要改归约方式。
- \(C=10\)，执行 10 步再规划（不要用 SFT 的 35/50）；Critic:Actor=2:1；\(\gamma=0.99\)；\(\tau=0.005\)。UTD=5 是**每条 transition** 5 次梯度，实现为 `utd * result.added`（不乘 `C/stride`）：单环境下一个执行 chunk 就是一条 transition，`num_envs=N` 时一次 collect 产出 N 条，固定次数会把梯度/数据比静默除以 N。
- **并行环境已解锁**（2026-09-02 用户改判原「V1 单环境」，细节见 [`docs/online-rl/stage2_survey.md`](../online-rl/stage2_survey.md) 13.2）。当前正式训 YAML 是 `num_envs=16`、`reconfigure_every_episodes=16`、`total_env_steps=1000000`。结束的 env 在当前 chunk 结束时用 ManiSkill 局部 reset（`options={"env_idx": ...}`）立即重开，空转最多 `C-1` 步；`episode_id` 由 collector 全局分配，`episodes.jsonl` 另带 `env_index`。**`num_envs>1` 时必须设 `reconfigure_every_episodes>0`**（`--check` 强制）：ManiSkill 对并行环境用 `reconfiguration_freq=0`，而 peg 长度/半径只在 `_load_scene`（reconfigure）时随机，实测普通 reset 与局部 reset 都不改 `peg_half_sizes`，不加周期性 reconfigure 整个 run 只会见到 `num_envs` 种几何。带 reconfigure 的全量 reset 约 0.55 s（N=4），会作废进行中的 episode，所以那一刻的 pending chunk 被丢弃而不跨 reconfigure bootstrap。局部 reset 的 `truncated` 安全性已实测：`TimeLimitWrapper` 读逐 env 的 `elapsed_steps`，只清零选中的 env。
- **动作边界不是 ±1。** checkpoint 的 `ACTION` 归一化是 `MEAN_STD`（z-score），演示范围约 ±2~5。Actor 的安全 clip 由 `src/smolvla_rltoken/vla/action_bounds.py` 从 checkpoint 的 `norm_map` + `action.min/max` 逐维推导，再乘 `action_bound_margin=1.5`；MIN_MAX / quantile checkpoint 会自动回到 ±1。**只 clip Actor 输出**：warmup 逐位执行冻结 VLA 的 reference（与 SFT eval 同一条链），reference 越界只做诊断计数。曾经写死的 `action_clip=1.0` 会砍掉约 70% 关节行程（86% 的训练帧至少一维被截断），warmup 成功率会塌到 0。`--check` 打印解析出的边界。
- warmup **32000** env step 纯 VLA 填 buffer（`num_envs=16` 时取 `16*200` 的整数倍，避免 warmup 切在半局）；结束后先 `offline_updates_after_warmup=1000`，再让 Actor 控环境。V1 无 stride ⇒ 一个执行 chunk = 一条 transition，所以必须 `warmup_env_steps >= batch_size * chunk_len`（`--check` 强制），否则冷启动一次都跑不了、Actor 用随机权重上手。`run_offline_updates` 返回真实执行次数，0 次时训练循环打 WARNING。buffer 不够 `batch_size` 时跳过 update。
- 训练循环记 episode 级指标：warmup 期（纯 VLA）与 Actor 期成功率分开（混合 episode 计入 Actor），最近 20 个 episode 的滑窗成功率与平均步数，逐 episode 落 run 目录下的 `episodes.jsonl`。这是判断 Actor 是否优于 SFT 22% baseline 的唯一在线依据。
- 批量 collect 里结束的 env 必须立刻停止记录：PegInsertion 成功后 `info["success"]` 会一直是 True，否则会写出 `r=1, n_steps=1, terminated=1` 的垃圾 transition。现在的做法是当前 chunk 结束后对这些 env 做局部 reset 并重新计数（早期版本是冻结陪跑到全批结束，已替换）。训练收尾 `flush_pending()` 补写最后一个中段 chunk。
- Stage 2 extractor：`extract(..., use_cache=True)` 一次 prefix 得到 hidden + KV，再 `sample_reference_chunk`。Stage 1 默认仍 `use_cache=False`。
- 冻结 VLA 与 encoder；不加载/不使用 decoder 前向。动作与 proprio 在 SFT preprocessor 归一化空间（8 维动作、9 维 qpos）。
- `--check` 不加载 VLA/仿真。`--smoke` 默认 mock VLA+env，在 `outputs/online_rl_smoke/mock_smoke_YYYYMMDD_HHMMSS/` 下写一次运行。`--gpu-smoke` 加载真实冻结 SmolVLA + encoder + `physx_cuda` 并行环境（默认 `num_envs=4`），写入 `outputs/online_rl_smoke/gpu_smoke_envN_YYYYMMDD_HHMMSS/`，并在 `benchamrk/rl/` 记录 GPU 利用率 / 显存 / 进程 RSS / cgroup 内存峰值。不要把文件直接写进 `outputs/online_rl_smoke/` 父目录，也不要删掉同级其它 run。正式训当前 YAML 是 `num_envs=16`、`total_env_steps=1000000`，写入 `outputs/online_rl/run_YYYYMMDD_HHMMSS/`，启动器拒绝 Cursor/Codex agent。
- 评测入口 / 完整 `benchamrk/rl/` 成功率评测 **尚未做**；GPU smoke 的资源记录除外。成功真值仍将是 `info["success"]`，RL 执行长度仍是 \(C=10\)。
